# 深空当铺：可能是偷的——交易判断、生产链与两种店铺的取舍

收录日期：2026-11-17

最近核实：2026-11-17，Asia/Shanghai

研究状态：官方玩法定位已核实；操作细节部分来自二手指南；未安装、试玩或阅读商业源码。

## 一句话结论

《深空当铺》的核心不是“更高级的寿司店”，而是**验货、议价、判断交易对象并承担后果**。第一款游戏的武器素材店可以借它的商品判断与特殊订单；寿司酒馆仍适合保留《潜水员戴夫》的“捕获食材—菜单—收入—探索”逻辑。建议分店借鉴，不整体替换。

## 技术实现

这是**基于公开玩法的系统拆解**，不是对商业游戏代码结构的宣称。

### 1. 主循环：每件货物都是一个判断题

```text
拿到报价或原料
→ 检查商品状态、真伪、交易对象与风险
→ 接受 / 拒绝 / 议价 / 举报等选择
→ 转卖，或先检测、净化、修理、改装、加工
→ 影响利润、库存、声望与后续来客
→ 支付经营成本、扩店，再接下一笔交易
```

官方介绍明确包含商品鉴定、讨价还价、派系关系、生产机器、许可证、赃物/违禁品风险和不断上升的租金。商品状态与顾客身份会让“便宜进货、贵价卖出”不再是无条件正确答案。[S1、S2]

### 2. 五种相互影响的乐趣

| 层 | 玩家真正考虑的事 | 官方或指南依据 |
| --- | --- | --- |
| 商品判断 | 是真货吗、质量如何、需要加工吗，亏损由谁承担 | S1 的鉴定、香烟、水、武器和化学品介绍 |
| 交易取舍 | 少赚一点换信誉，还是承担更高风险；何时拒绝 | S1、S2 的议价、声望与交易后果 |
| 库存与现金 | 钱够不够交租、货能否转手、容器/设备是否放得下 | S1 扩张/库存；S3 操作说明 |
| 生产链 | 不只倒卖，还能测试、过滤、改装、制造更有价值的商品 | S1 的职业与机器；S3 的生产路线 |
| 顾客与世界反馈 | 商品吸引不同买家，政治关系和身份判断影响以后 | S1、S2；S3 展示柜说明 |

**重要修正：它并非只有站柜台，也有生产经营和夜间外出等内容。** 但它用于本次比较的强项仍是交易判断与社会后果，不是房间清怪、翻滚采矿的动作地牢。不能说“完全没有自动化/战斗”，也不能因为有库存和制作，就当作与戴夫相同。[S1–S3]

第三方指南具体描述了用放大镜找问题、选择对质理由、展示柜影响来客、议价前查看概率/声望，以及库存整理操作。这些是**二手操作说明，未实机核验**；不把指南给出的房租、许可证费用、顾客人数、版本数值复制进我们的游戏。[S3]

### 3. 借鉴时需要什么数据与事务

若独立做一个轻量经营判断层，建议分为：

- `ProductDefinition`：商品种类与公开品质规则。
- `TradeOffer`：报价、库存归属、成交状态。
- `InspectionResult`：玩家实际发现了哪些线索，不能凭“点检查”免费获得最优售价。
- `CustomerNeed`：普通需求与委托需求分开。
- `TradeOutcome`：扣钱、扣货、入货、声望和事件效果一次提交。

这是我们的设计建议，不是原游戏类名。成交失败不扣款；读档、重复确认不重复结算；锁定自用装备不进入报价；加工失败和退货要有明确规则。复用生产线与库存事务，比另起一个完全独立的交易库存更稳。

## 与戴夫、夜勤人及第一款游戏的关系

本轮现场读取第一款游戏 `AGENTS.md`、`docs/01-game-outline.md`、`docs/04-code-references.md`、`docs/06-open-questions.md`，HEAD 为 `d818b56`。这里仅保留回答所需的设计摘要，不转载内部大纲、私有研究源码、人物清单或数值。

**当前事实：前期市中心武器素材店，后期海滩寿司酒馆；两者允许自动营业、玩家离店。新品试价和顾客反应已经存在。** 因此“加入深空当铺”不能被解释成重新加入已经有的定价功能。

| 比较项 | 夜勤人 | 潜水员戴夫 | 深空当铺 | 对当前项目的判断 |
| --- | --- | --- | --- | --- |
| 主要资源入口 | 冒险拿战利品 | 下海捕食材 | 交易进货、生产及其他获取途径 | 矿物与水产要继续支撑我们的生产线 |
| 店里最突出的事 | 上架、试价、库存与售卖 | 食材变菜单，服务顾客，收益再投探索 | 验货、谈价、看人、处理社会后果 | 不应把两种店变成相同的小游戏 |
| 探索联系 | 装备与战利品闭环 | 捕到新食材形成新商品 | 店铺生存和交易关系是主轴 | 戴夫最能保持寿司店与捕鱼联动 |
| 可借的经营深度 | 价格知识与上架 | 菜单组合、特色客人、经营升级 | 质量判断、特殊需求、报价取舍 | 武器店借鉴，寿司店不换主循环 |

夜勤人的动作、战利品与经营依据来自官方页；戴夫的白天下潜、晚间寿司、收益升级潜水装备，以及招募员工，来自 Steam 和 PlayStation 官方页。[S4–S6]

### 建议：用在武器店的可选深度，而不是整店替换

**值得借，但等用户确认再实现：**

1. **少量特殊订单**：顾客要某种用途的工具或装备，玩家决定交哪件、赚现金还是换长期关系。先复用委托板，不必让所有路人都谈一次价。
2. **少量旧货翻新/品质判断**：在武器素材店作为支线尝试，帮助消耗加工产物；必须明确来源、鉴定成本和是否真的有可卖库存。
3. **有提示的需求变化**：小镇修复活动带来短期订单，让生产计划有方向。先做需求数量变化，不一上来增加复杂动态价格系统。

**不建议首版引入：**

- 强制逐客鉴定/议价：会让离店自动经营失效，玩家被柜台占住。
- 租金不断上涨、查抄、走私、派系生存：原游戏主题强，但会把温暖的小镇重建转成高压谋生；不等于这种玩法差，只是不符合当前主轴。
- 全商品品质随机化、真假货、保质期、负面信誉连锁：数据、库存、存档与说明成本一起增长；没有必要为“更深”同时开这些系统。

**已有自动经营不是硬性排斥有趣交易。** 普通销售仍自动，特殊顾客转成可暂存的委托；玩家有空再参与。若以后想改成“亲自经营是主玩法”，需要明确重做玩家时间分配，而不是把它当小功能追加。

### 寿司酒馆应该怎么借戴夫

优先保留“亲自捕获/养殖—处理食材—配菜单—供餐—赚取探索资金”。戴夫官方有员工和服务顾客；我们的现定版本是自动供餐与结账，**不是一比一复刻戴夫服务操作**。[S5、S6]

若觉得自动营业太被动，可以先增加菜单选择、特别委托或可选短时服务事件；不要让每晚强制跑堂与夜间下矿同时成为必做。也不要未经确认加“每日没用食材全报废”等惩罚。

## 复现路径

**以下是建议的独立最小验证，未实际运行；不是照抄原游戏。**

1. 先实现当前武器素材店的真实库存、试价、自动结账与离店营业，作为基线。
2. 只增加一个可选特殊订单，不加派系、租金或真假货系统。
3. 让同一份材料产生两个可解释选择：现在卖现成商品，或按委托加工再交付。
4. 测试玩家忙于农场/下矿时是否还能正常经营；委托延期或拒绝不要惩罚普通营业。
5. 验证扣料、加工、交付、收款与读档，不能重复收钱、误卖自用武器或卖不存在的货。
6. 对比“原版店”与“加一条委托的店”：玩家是否理解选择、是否更想安排生产、是否被迫频繁回店。没有实测前不宣称更好玩。

## 适用场景与限制

适合想把**判断人和货**做成主乐趣的游戏；不适合仅为了店铺更复杂，就把租金、犯罪、身份识别和经营压迫完整移植进种田自动化项目。

开发工作量的判断是定性分析，不是工期报价：若全换，新增商品状态、买卖报价、检查界面、客户事件与经营失败逻辑，还会牵动自动经营和一天安排。第一款游戏正式本体尚未开工，重做机会仍有，但应由主题与目标体验驱动，而非追热点。
